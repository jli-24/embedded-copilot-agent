# v0.12.0 Supervisor × Knowledge Gateway Integration 实施计划

## 目标

在保持 v0.11 公共契约和无 Gateway 运行路径不变的前提下，将显式注入的
`KnowledgeGateway` 集中接入同步 `SupervisorAgent`：

```text
AgentTask -> Requirement Analyzer -> Knowledge Query Builder
          -> Knowledge Gateway -> Knowledge Context -> Planner
          -> Dispatcher + domain adapters -> domain Agents -> Aggregator
```

## 所有权与依赖边界

- Gateway invocation ownership belongs exclusively to `SupervisorAgent.run()`。
- 每次 run 最多调用一次 `KnowledgeGateway.search()`，不重试。
- Planner、Dispatcher、adapter 和领域 Agent 不持有或调用 Gateway。
- 领域 Agent 不导入 `KnowledgeContext`、`ExecutionContext` 或 Supervisor trace。
- Supervisor adapter 将 `KnowledgeResult` 转换为现有领域 document/evidence 模型。
- `knowledge_gateway=None` 完整保留 v0.11 的 dispatcher 和本地 retriever 行为。

## 安全数据流

- Builder 只生成 canonical topic、allowlisted keywords 和 domains。
- Query 在 Gateway 前重新验证、deep copy，并在调用前后比较稳定快照。
- Gateway 结果遵循当前公开返回契约，逐项重新验证并保持顺序。
- Planner 只看到 `_supervisor_knowledge` 下的 domains、result count、safe categories 和
  hit flag；该 namespace 不进入公开 plan/result。
- Child metadata 只包含领域知识、安全 provenance 和 centralized mode 标记。
- Trace 只包含 `stage`、`status`、`target`、`domains` 和 `count`。

## TDD 与兼容性

测试顺序为 RED -> GREEN -> REFACTOR，覆盖 query、context、mutation isolation、单次调用、
四领域 centralized mode、Debug routing、trace、Benchmark injection 和旧路径回归。固定
v0.11 的领域输出与 Benchmark JSON schema hash、Gateway 签名及 Health 字段结构；仅现有
版本来源和 version literal 更新为 `0.12.0`。

## 禁止范围

不新增 Provider、HTTP、GitHub API、下载、LLM、LangGraph Runtime、Settings 配置、Health
字段、自动修复、编译、烧录或硬件控制。不创建 tag，不 push。
