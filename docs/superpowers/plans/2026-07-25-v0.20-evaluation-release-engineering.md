# v0.20.0 Evaluation & Release Engineering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增隔离、离线、确定性的 Evaluation Layer，升级 Streamlit 展示、发布文档、CI 和版本元数据，同时保持全部运行时核心接口与行为兼容。

**Architecture:** `embedded_copilot.evaluation` 只观察显式注入的 Supervisor，复用现有 synthetic integration dataset 和 Supervisor input adapter，把 `EngineeringReport` 投影为安全的 evaluation-only models。Web 只消费 FastAPI client、`EngineeringReport` 与安全的 evaluation snapshot，不 import 或执行 Runtime Agent；Release/CI 通过离线测试和 schema snapshot 固化兼容性。

**Tech Stack:** Python 3.11、Pydantic v2、pytest、FastAPI contract tests、Streamlit、GitHub Actions、Ruff。

## Global Constraints

- 不修改 Input Layer、Supervisor、Integration Layer、Knowledge Gateway、Provider Contract、PCB/Datasheet Parser、领域 Agent、Agent API、benchmark public models、`EngineeringReport` schema 或 FastAPI contract。
- 不新增 Agent、Parser、Provider、Workflow node、LLM judge、外部服务、数据库、缓存或索引。
- Evaluation 不读取附件内容或目录，只通过 `UnifiedInputContext.model_validate()` 和 `attach_input_context()` 注入 metadata-only context。
- Evaluation 输出不得包含 request、attachment metadata、文件名、路径、token、fixture body、原始异常、traceback、`AgentResult`、PCB/Datasheet model 或用户数据。
- total latency 使用 injected monotonic clock 直接观测并 round 到 6 位；`agent_latency_status` 固定为 `"unavailable"`，不得估算逐 Agent 耗时。
- 所有新增行为严格执行 RED -> GREEN -> REFACTOR；先 focused tests，再相关回归和完整离线测试。
- 最终版本统一为 `0.20.0`；最终只创建 `feat: add evaluation and release engineering` 功能提交，不创建 tag、不 push。
