# Embedded Copilot v1.0.0 Release

## Overview

Embedded Copilot v1.0.0 将 v0.49–v0.57 Engineering Core 与 Product Layer 汇总为面向
嵌入式研发的 AI Embedded Engineer。系统通过 immutable、caller-owned、deterministic 的
工程合同连接需求、方案、验证、执行、反馈和优化阶段，并最终生成可追踪的工程发布报告。

本版本坚持 proposal-first、human approval 和 safe execution boundary。结构化结果表示工程提案、
安全投影或已完成的受控调用，不自动升级为物理硬件事实或产品认证结论。

## Architecture

```text
Requirement
  -> Architecture
  -> Hardware
  -> Firmware
  -> Validation
  -> Artifact
  -> Execution
  -> Feedback
  -> Optimization
  -> Engineering Report
```

Product Layer 使用 caller-owned `EngineeringWorkspace` 聚合各阶段的安全 reference、fingerprint、
状态、时间线、review counts 和 decision history。它不维护 project registry、workspace store、
cache 或 persistence，也不取代 Workflow、Memory、Repository 或 Release System 的生命周期职责。

## Major Features

- Requirement Intelligence 与 Engineering Architecture planning
- Hardware Engineering Proposal
- Firmware Engineering Proposal
- Hardware Validation Report
- Engineering Artifact Projection
- approval-bound Engineering Execution Report
- Human Feedback Loop 与 Revision Proposal
- Autonomous Optimization mathematical proposal loop
- Product `EngineeringWorkspace`、`ProjectSession` 和 Dashboard Projection
- Timeline Projection 与 `EngineeringReleaseReport`

## Engineering Workflow

Requirement Intelligence 先将输入需求转为严格、带 fingerprint 的工程合同。Hardware 与 Firmware
阶段只形成待审核方案；Validation 阶段只依据合格 evidence 生成安全分析；Artifact 阶段生成内存
投影，不生成源码、PCB 或可执行文件。Execution 必须通过显式 policy、approval 与 adapter binding，
Feedback 和 Optimization 则继续产生可审查的 change/revision 或 mathematical candidate。

最终 Product Layer 只聚合跨阶段 reference，不自动调用上述 Runtime，也不隐式修改 caller-owned
snapshot。

## Security Model

- Workspace Runtime 仍是文件修改边界；Product Layer 不写文件。
- 外部调用必须经过 typed Port、permission、approval、verification 和 audit 边界。
- snapshot 与报告只保存安全 projection、reference 和 fingerprint，不携带 raw payload、日志或设备内容。
- Product Runtime 无内部 registry、store、cache、persistence 或隐藏状态。
- 不自动制造。
- 不自动修改 PCB。
- 不提供无人值守硬件控制。
