# Embedded Copilot v0.47 Hardware Intelligence Layer

Status: Released

## Purpose

v0.47 introduces a framework-independent, observation-only Hardware Intelligence
Runtime. It combines caller-owned digital-twin projections, structured telemetry,
HIL reference projections, and deterministic validation into immutable snapshots.

```text
Successful Execution Snapshot
  -> safe Hardware Context Projection
  -> deterministic Digital Twin Projection
  -> structured caller-owned observations
  -> HIL reference projection
  -> validation projection
  -> Hardware Intelligence Snapshot
```

The Runtime exposes one `HardwareIntelligencePort`. Provider connections and their
lifecycle remain owned by the composition caller. Public snapshots contain only
safe references, structured finite metrics, fingerprints, lifecycle state, and
sanitized failure codes.

## Validation Boundary

Validation covers schema conformance, deterministic simulation outputs, explicit
threshold checks, and contract bindings. A `VALIDATED` snapshot means those
software projections passed the injected validation policy. It does not mean that
the board, device, electrical design, or firmware was physically validated.

Human approval is fingerprint-bound to an observation-ready snapshot. Approval is
required before the validation port is invoked. Denial produces an immutable
terminal projection and does not invoke downstream validation.

## Security Boundary

- No serial, USB, debugger, network, filesystem, database, Shell, or Git access.
- No Build, Flash, reset, programming, device control, or hardware mutation.
- No background collection, cache, persistence, system clock, or generated IDs.
- No Agent, Supervisor, Tool Runtime, Knowledge, or Memory implementation access.
- Execution integration accepts only a typed, successful, verified public snapshot
  and projects safe reference identifiers without reading artifact bodies.

## Non-goals

v0.47 does not provide real hardware transport, physical HIL execution, automated
test equipment, PCB validation, electrical certification, hardware control, or
production hardware verification. Deterministic providers used by tests are test
fixtures and are not evidence of observed hardware behavior.
