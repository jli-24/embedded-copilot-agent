# v3.0 Engineering Memory Platform

v3.0 extends the existing memory system with an approved engineering fact layer.
It does not add a Runtime Agent, Workflow node, model, embedding provider, network
service, database, or execution capability.

## Lifecycle

```text
Conversation Snapshot
  -> Memory Candidate
  -> Human Approval
  -> Approved Engineering Memory
  -> Knowledge Evolution
  -> Markdown Projection
  -> Obsidian
```

Conversation produces candidates only. Pending or rejected candidates cannot be
stored, retrieved, projected, or written as Markdown.

## Approval Boundary

The approved-fact layer accepts only a fingerprint-bound approval with a valid
project, reviewer, decision, timestamp, and candidate identity. Requirement,
Architecture, Decision, and Interface facts are supported when their source data
is safe. Debug, Optimization, Validation, and Tradeoff facts remain rejected or
unavailable when evidence is insufficient; no domain fact is fabricated.

## Store and Retrieval Boundary

The v3.0 approved-fact Store is additive to the existing Engineering Memory state
machine. It stores immutable approved facts and exposes deterministic, project-bound
retrieval. Retrieval returns approved facts only and never invokes Agents, Tools,
Build, Flash, Device, Workspace, models, embeddings, or network services.

The existing approved-fact Store/Port is the single implementation boundary. Its
canonical operations are `create_record`, `get_record`, `query_records`,
`retrieve_verified`, and `fingerprint_check`. The existing `save`, `get`, and
`list` methods remain compatibility facades over the same store; no second Store,
Record schema, or Promotion service is introduced.

## Knowledge Evolution Boundary

Knowledge Evolution consumes read-only approved Engineering Memory projections. It
does not create candidates, approve memory, write the Store, or convert knowledge
back into memory.

## Markdown Projection Boundary

Knowledge Writer consumes approved projections only and writes deterministic files
under `docs/knowledge/99_Memory/`. Markdown and Obsidian are projections for viewing,
search, and graph visualization. They are not a Memory source and cannot trigger
Runtime or engineering execution.

## Runtime and Promotion Restrictions

Promotion is the only path from an approved Candidate to an Engineering Memory
fact. Runtime Agents have no Memory mutation capability. Engineering Context
consumes only approved or verified projections and never writes back to Memory.
