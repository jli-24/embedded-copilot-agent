# Embedded Copilot v0.46 Execution Integration Layer

Status: Released

## Purpose

v0.46 introduces a framework-independent boundary between verified agent proposals
and caller-provided controlled executors. It prepares immutable execution plans,
binds one exact executor, requires typed Human Loop approval, verifies projected
results, and returns deterministic terminal snapshots.

## Data Flow

```text
Successful Agent Execution Snapshot + Proposal Projection
  -> Execution Preparation Request
  -> Fingerprinted Execution Plan
  -> Exact Executor Binding
  -> READY Snapshot
  -> Typed Human Review Proof
  -> Controlled Invocation
  -> Verification Projection
  -> Terminal Execution Snapshot
```

The runtime never selects an executor from artifact content. The caller explicitly
provides the executor type, and the registry performs one exact resolution with no
fallback or discovery.

## Human Approval and Replay Boundary

Execution requires a deep-copied, revalidated `HumanReviewSnapshot` in the
`COMPLETED` and `APPROVED` state. The review must bind the same proposal and READY
snapshot. Rejection and revision requests produce terminal cancellation snapshots.

READY bindings are process-local and single-use. The first valid decision consumes
the binding atomically. Sequential and concurrent replay are rejected. Persistence
and replay protection across process restarts are explicit non-goals.

## Security Boundary

Public snapshots contain only safe summaries, reference identifiers, finite metrics,
fingerprints, lifecycle state, and sanitized failure codes. Live executors, registry
objects, review comments, artifact bodies, commands, paths, stdout, stderr, and
provider exceptions never enter public contracts.

v0.46 does not provide real executors and does not perform Build, Flash, Debug,
Shell, Git, network access, filesystem mutation, or hardware control. Deterministic
executor implementations exist only in tests.
