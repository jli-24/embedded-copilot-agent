# Embedded Copilot v0.45.0

## Release Overview

v0.45.0 adds a framework-independent, human-controlled Human Loop Layer. It
binds safe Engineering Generation proposal metadata to an explicit review
decision, structured feedback, and a new reviewable revision proposal.

The Runtime is a review boundary, not an execution or mutation authority.

## Human Loop Architecture

```text
Engineering Generation Proposal
  -> Proposal Projection
  -> Human Review Lifecycle
  -> Feedback Projection
  -> Revision Context
  -> Revision Proposal Boundary
  -> Human Review again
```

`create_human_loop_runtime(...)` composes caller-owned typed Ports. The facade
exposes only `human_loop_port()` and does not expose review, proposal, feedback,
progress, configuration, or persistence implementations.

## Proposal Projection

The Proposal Projection contains only proposal identity, artifact type,
artifact version, summary, safe reference IDs, and a deterministic SHA-256
fingerprint. Raw artifacts, source files, CAD or PCB data, firmware content,
generation prompts, hidden reasoning, and tool output do not cross this
boundary.

## Human Review Lifecycle

The lifecycle supports explicit human decisions: `APPROVED`,
`CHANGES_REQUESTED`, and `REJECTED`. Reviewer identity, decision, optional safe
comment, proposal fingerprint, and caller-provided UTC timestamp are bound into
the review projection. Human Review changes state only; it does not execute a
modification or infer an approval.

## Feedback Projection

Feedback Projection transforms an explicit change request into a structured
change type, target reference, constraint, priority, and safe reference. The
Runtime does not reinterpret free-form feedback as a command, invent design
constraints, or produce Tool actions.

## Revision Context

Revision Context binds the original proposal fingerprint, reviewed feedback
fingerprint, verified Knowledge reference, and Engineering Memory read
reference. The context is immutable and does not mutate Knowledge, Memory, or
the original Artifact.

## Revision Proposal Boundary

A revision contains only its caller-owned ID, base proposal ID, structured
changes, safe rationale summary, and fingerprint. It remains a proposal and
must enter Human Review again. The Human Loop Layer does not apply it to an
engineering artifact or workspace.

## Progress Event Isolation

Progress events contain only sequence, proposal ID, lifecycle state, event, and
caller-provided timestamp. A progress sink failure is fail-closed: the Runtime
does not retry, continue downstream processing, or return partial state.

## Security Boundary

The Human Loop Layer does not import or call Supervisor or Agent
implementations, Workflow internals, Knowledge internals, Engineering Memory
Store, Tool Runtime, Workspace write, Build, Flash, Hardware Debug, Shell, Git,
subprocess, network, filesystem, database, persistence, or dynamic import.

## Validation

Release candidate validation includes Human Loop focused and security tests,
v0.40-v0.44 regression tests, the complete offline pytest suite, Ruff, scoped
Black, compileall, pip check, Git diff validation, version drift checks, and
protected Runtime hash verification.

## Non Goals

v0.45 does not provide automatic approval, artifact mutation, Agent execution,
Tool execution, Build, Flash, Hardware Debug, Memory writes, Knowledge mutation,
API endpoints, UI, or an autonomous revision loop. It does not claim that a
reviewed proposal has been applied to engineering state.
