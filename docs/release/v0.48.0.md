# Embedded Copilot v0.48.0

## Overview

v0.48.0 introduces a framework-independent, deterministic, proposal-only
Optimization Layer. It converts typed hardware observations into bounded,
reviewable mathematical candidates. It does not execute an optimization action.

## Architecture

```text
Hardware Observation Projection
  -> Optimization Plan
  -> Unverified Optimization Proposal
  -> Deterministic Evaluation Projection
  -> Human Approval
  -> Reviewed Optimization Result
```

## Optimization Runtime

The facade exposes only `OptimizationPort`. A caller-owned exact registry resolves
one algorithm for the fixed target/algorithm pair. There is no fallback,
discovery, dynamic import, provider lifecycle, or hidden execution path.

Requests, plans, proposals, evaluations, approvals, progress events, and snapshots
are frozen strict DTOs with tuple-only collections and deterministic SHA-256
fingerprints. Typed boundaries use deep-copy revalidation without serialization
round-trips.

## Mathematical Algorithms

- PID is a stateless formula that projects a bounded controller-output candidate.
- Power applies a fixed five-percent current and power candidate reduction while
  preserving temperature and voltage.
- Performance applies a fixed `1.05` projection to latency and throughput while
  preserving CPU and memory observations.

Every algorithm returns `candidate_semantics="unverified"`. These models provide
mathematical candidate only results and are not real controllers or validated
optimization claims.

## Evaluation Projection

The deterministic evaluator compares before and after metrics and produces
per-metric delta and percentage projections. A zero baseline produces no
percentage value. The evaluator does not calculate a total score, infer hardware
behavior, or claim measurement evidence.

## Approval Flow

Human Approval is bound to the evaluated snapshot, proposal, evaluation,
reviewer, and caller-provided UTC timestamp. Approval returns a reviewed immutable
result; it does not apply settings or control a device. Runtime-local duplicate
and consumed-approval rejection provide process-local Replay Protection only.

## Security Boundary

- No Agent, Supervisor, Workflow, Knowledge, Memory, Tool, or protected Runtime
  implementation access.
- No filesystem, database, Shell, Git, network, serial, USB, device SDK, cache, or
  persistence.
- No generated IDs, system clock, background task, dynamic import, or fallback.
- No firmware mutation, Flash, Debug, hardware write, or control operation.
- Dependency failures produce sanitized terminal snapshots or boundary errors.

## Non Goals

v0.48 provides no hardware control, no real tuning, and no measurement capability.
It does not provide a real PID controller, online parameter tuning, power control,
firmware modification, Flash, Debug probe, Serial, USB, persistent optimization
history, model training, or autonomous optimization.
