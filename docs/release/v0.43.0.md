# Embedded Copilot v0.43.0

## Release Overview

v0.43.0 adds a framework-independent, controlled-execution Agent Execution Layer.
It accepts an explicitly projected workflow task, resolves one registered agent
capability, verifies the typed result, and returns an immutable execution snapshot.

## Execution Runtime

The `AgentExecutionRuntime` facade exposes only `execution_port()`. Execution uses
caller-owned identifiers and UTC timestamps. The Runtime does not generate IDs, read
the system clock, retain cross-request state, or infer an agent from task text.

## Agent Binding

Explicit Agent Registry Binding uses exact `agent_type` matching with no fallback,
module scan, or dynamic import. `AgentCapabilityBinding` carries safe fingerprinted
metadata and a caller-owned live execution port. The port is never serialized,
fingerprinted, cached, persisted, or stored in an execution snapshot.

## Lifecycle

The Execution Lifecycle State Machine follows:

```text
CREATED -> READY -> RUNNING -> VERIFYING -> SUCCESS
```

Terminal alternatives are `FAILED`, `TIMEOUT`, `WAIT_HUMAN`, and `CANCELLED`.
Each dependency is invoked at most once per attempt and no automatic retry occurs.

## Verification

Agent output crosses an exact typed boundary using deep copy, revalidation, and
fingerprint verification. Safe Result Projection permits only status, a safe summary,
artifact references, and finite metrics. The independent Verification Boundary must
accept the bound result before a successful snapshot is returned.

## Failure Handling

Registry, agent, timeout, invalid-result, and verification failures return a sanitized
Fail-safe Execution Snapshot. Snapshots do not expose provider exceptions, paths,
credentials, prompts, reasoning, logs, raw output, or partial verification state.

## Recovery

Two-phase Human Resume first moves an eligible attempt-one failure to `WAIT_HUMAN`.
A separately bound `APPROVED` decision may start attempt two. Denial cancels execution;
binding mismatch, replay of an old snapshot, or a second failed attempt is rejected.

## Workflow Adapter

The adapter projects only the public Workflow task contract. The caller explicitly
provides execution/workflow IDs, agent type, context ID, typed reference IDs,
constraints, and timestamp. It does not inspect DAG internals, mutate workflow state,
or infer agent selection from free text.

## Security Boundary

The Runtime is independent of Supervisor, LangGraph, Knowledge internals, Engineering
Memory storage, Tool Runtime, Workspace write, filesystem, network, database, Shell,
Git, subprocess, cache, persistence, and background execution. Progress Event
Isolation limits events to sequence, execution/workflow IDs, state, and caller time.

## Non Goals

v0.43 does not execute Build, Flash, Hardware Debug, or Tool Runtime capabilities. It
does not add firmware/PCB generation, workspace mutation, autonomous agent discovery,
automatic approval, automatic retry, API endpoints, or UI integration.
