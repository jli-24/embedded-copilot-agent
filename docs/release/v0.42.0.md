# Embedded Copilot v0.42.0

## Release Overview

v0.42.0 新增 framework-independent、planning-only 的 Agent Workflow Layer。Runtime 将
caller-owned requirement、可信上下文、风险投影、工程规划、任务 DAG、人工审批和确定性调度
组合为可验证的工作流准备流程，但不执行任何任务。

## Workflow Runtime Foundation

- `WorkflowRuntime` facade 只公开 `workflow_port()`。
- Requirement Agent Port、Workflow Context Port 和 Engineering Planning Agent Port 均由调用方注入。
- 所有 DTO frozen、strict、`extra="forbid"`、tuple-only，并使用确定性序列化和 fingerprint。
- Agent/Port typed output 经 exact type check、deep copy、revalidation 和 fingerprint 复核后才可接受。
- Runtime 不读取系统时钟、不生成 ID，也不维护跨请求状态。

## Context and Risk Projection

`WorkflowContextPort` 是外部 composition boundary。Knowledge、Memory 和未来 Project Context
adapter 可以在该边界后组合；Workflow Runtime 只能看到 metadata-safe
`WorkflowContextProjection`。

Risk Projection Boundary 只接受绑定到 VERIFIED source reference 的结构化风险。Risk 仅用于
Planning visibility、Human Approval context 和 progress/reporting，不得改变 task priority、
scheduling order、DAG、dependency generation 或 Agent selection。

## Planning, DAG and Scheduling

Engineering Planning Agent 生成的 typed plan 经 Runtime 复核后投影为 Frozen Task DAG。DAG 拒绝
缺失 dependency、duplicate/self edge、cycle 和超出容量的任务集合。Deterministic Scheduler
使用固定排序的 Kahn algorithm 生成 scheduling batches，但不调用 Agent、Tool、Executor 或
Supervisor dispatcher。

## Human Approval

`prepare_workflow()` 在 `WAITING_APPROVAL` 停止。WorkflowApprovalContext 必须完整绑定 workflow、
requirement、context、risk、DAG 和 waiting snapshot fingerprints。APPROVED 后才生成完整 schedule；
DENIED 或任一 binding mismatch 均不得产生 partial scheduling。

## Progress Events

Progress Events 只包含 sequence、workflow ID、event、state、count 和 caller-provided timestamp。
事件不包含 requirement body、risk description、evidence、Memory record、prompt、hidden reasoning
或内部异常。Progress sink 失败时 fail closed，不 retry，也不返回 partial snapshot。

## Security Boundary

- Workflow Runtime 不导入 Supervisor、Planner/Agent implementation、Knowledge internals 或
  Engineering Memory Store。
- 不调用 Tool Runtime、Workspace write、Build、Flash、Debug 或 hardware control。
- 不使用 Shell、Git、subprocess、network、filesystem、database、environment、cache、persistence、
  background task 或 dynamic import。
- Workflow Runtime 只规划和调度批次，不执行 task，不生成 firmware/PCB，也不选择实际 Agent。

## Validation

Release Preparation 将执行完整 pytest、Ruff、限定 manifest 的 Black check、compileall、pip check
和 `git diff --check`。最终结果在 release commit/tag 前确认。

## Non Goals

本版本不包含 task execution、Tool execution、firmware generation、PCB generation、build、Flash、
文件修改、hardware control、Supervisor replacement、Knowledge-driven scheduling、自动审批、重试
工作流或后台执行。
