# Embedded Copilot v0.33.0

## Added

- `embedded_copilot.workspace_runtime` provides trusted-root workspace snapshots, strict unified-diff validation, approval-gated text-file mutation, and content-free audit events.
- `WorkspaceRuntime` exposes only `workspace_port()` through `create_workspace_runtime(workspace_root)`.

## Architecture Boundary

The Workspace Operation Layer is a framework-independent Runtime, not an Agent or workflow. It does not provide API, UI, IDE, Shell, Git, build, model, or hardware-control capabilities.

The factory receives one trusted root. Requests can inspect only explicit safe relative paths; the runtime does not scan directories. Descriptor-derived file and parent-directory identities are checked during reads and again immediately before writing. The private writer only accepts a fully prepared internal change plus an `APPROVED` context bound to the proposal, workspace, snapshot, targets, approver, and caller-supplied UTC time.

All target outputs and same-directory recovery backups are prepared before replacement. A partial write is rolled back in reverse order. A rollback failure returns `rollback_failed`, emits no success audit, and preserves recovery backups for manual intervention.

Every public port entry revalidates its frozen DTO. A metadata-only, process-local canonical proposal fingerprint binds the validated diff, reason, creator, snapshot, and targets to the proposal identifier before an approval can be applied.

## Validation

- Focused tests cover frozen snapshots, fingerprint stability, unsafe paths, strict hunk counts, CRLF preservation, parent/leaf identity drift, approval rejection, approved apply, rollback failure recovery, and content-free audit events.
- Static tests block Agent, Model/LLM, RAG, API, Streamlit, Git, network, Shell, and subprocess dependencies.

## Limitations

- v0.33 supports only modifications to existing UTF-8 text files represented in a snapshot. Mixed newline styles and text without a final newline are rejected.
- It does not generate patches, execute commands or builds, or control an IDE.
- Approval identity is a trusted caller boundary; v0.33 does not introduce a signing or approval service.
- Cross-platform identity and hash checks narrow path replacement races, but v0.33 does not add platform-specific POSIX `dirfd` or Windows native-handle write traversal.
- Atomic replacement preserves regular permission mode bits, but v0.33 does not preserve platform-specific ACLs or extended attributes.
- `APPLIED` reports that the process-level write and replacement calls completed. v0.33 does not claim crash or power-loss durability because it does not add directory `fsync` or a recovery journal.
- A caller must serialize `inspect_workspace()`, `validate_change()`, and `apply_change()` for each runtime instance. v0.33 does not add concurrent-apply coordination.
