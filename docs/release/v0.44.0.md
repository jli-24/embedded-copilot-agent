# Embedded Copilot v0.44.0

## Release Overview

v0.44.0 adds a framework-independent, approval-controlled Engineering Generation
Layer. It converts explicitly bound public Workflow and Agent Execution results into
immutable engineering artifact proposals for independent verification and human
review.

## Engineering Generation Architecture

```text
Requirement
  -> Workflow Task
  -> Agent Execution Result
  -> Generation Request
  -> Generator Registry
  -> Artifact Proposal
  -> Verification Boundary
  -> Human Approval
  -> Approved Artifact Reference
```

The Runtime remains an enhancement boundary. It does not control Workflow,
Supervisor routing, Agent Execution, Tool Runtime, or engineering state.

## Generator Registry

The Generator Registry Boundary resolves exactly one explicitly registered caller-owned
capability for `HARDWARE_DESIGN`, `FIRMWARE`, `PCB_DESIGN`, or `BOM`. Unknown or failed
resolution is rejected without fallback, module scanning, or dynamic import. Live
generator ports never enter serialization, fingerprints, or snapshots.

## Artifact Proposal

Every Artifact Proposal is frozen, strictly validated, deterministically serialized,
and SHA-256 fingerprinted. It contains a safe summary, typed structured output,
verified reference identifiers, and allowlisted metrics. It contains no prompt,
chain-of-thought, raw source body, filesystem path, or provider response.

## Hardware Design Generation

The Hardware Design Proposal projects reviewable MCU, peripheral, communication, and
power-architecture selections. It is a design proposal, not verified schematic,
electrical, or hardware evidence.

## Firmware Generation

The Firmware Proposal describes project structure, BSP, driver, middleware,
application, and FreeRTOS task boundaries. It does not generate source files, compile,
build, test, flash, or modify a workspace.

## PCB Proposal Generation

The PCB Design Proposal records reviewable placement rules, routing constraints, and
layer suggestions. It does not generate real PCB files, perform layout, or claim DRC,
ERC, signal-integrity, or manufacturing validation.

## BOM Proposal

The BOM Proposal records typed component, alternative, cost, and supply-risk entries
for engineering review. It does not query suppliers, guarantee availability, or make
procurement decisions.

## Verification Boundary

The Artifact Verification Boundary is an injected, typed `VALID`/`INVALID` projection.
It independently binds the proposal fingerprint before approval. v0.44 does not
implement compilation, DRC, build, or hardware testing behind this port.

## Human Approval

Every verified proposal stops at `WAITING_APPROVAL`. Approval must bind the generation
ID, artifact fingerprint, workflow ID, reviewer, and caller-provided UTC timestamp.
Only an explicit human `APPROVED` decision followed by the approval policy can produce
an Approved Artifact Reference; automatic approval and verification bypass are
forbidden.

## Security Boundary

Security Isolation keeps Engineering Generation independent of Supervisor and Agent
implementations, Knowledge and Engineering Memory internals, Tool Runtime, Workspace
write, LangGraph, LLM providers, filesystem, network, database, Shell, Git,
subprocess, cache, persistence, and background execution. Progress events contain only
sequence, generation/workflow IDs, state, and caller time.

## Non Goals

v0.44 does not generate real PCB files, modify project files, execute Build, execute
Flash, perform Hardware Debug, or replace Tool Runtime. It also does not write firmware
source, control hardware, invoke external engineering tools, or claim real build,
layout, electrical, or hardware validation.
