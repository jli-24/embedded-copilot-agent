# Embedded Copilot v0.39.0

## Summary

v0.39.0 新增 contract-first Engineering Memory Layer。它保存调用方明确提交的工程记忆，
用不可变 Record、Aggregate revision、operation receipt 和确定性状态转换隔离
`CANDIDATE` 与 `VERIFIED`，并提供稳定 snapshot 与 revision-bound history。

## Architecture

公开 facade 只暴露 `memory_port()`，同步 `execute()` 是唯一业务入口。固定执行顺序为
strict revalidation、`MEMORY_REQUESTED` audit、最小披露 permission、Store
operation/query、terminal audit、result。Permission 只接收九字段
`MemoryAuthorizationRequest`，不接收 payload、provenance、Finding 或审批正文。

v0.39.0 的唯一参考适配器是线程安全 `InMemoryEngineeringMemoryStore`。每个实例拥有
私有容器和 `RLock`；receipt、revision、状态转换、双记录替代、projection 和 receipt
写入在同一个锁保护的 Store 临界区内完成。它不是 real persistence。

## Deterministic State

- 新记录从 `record_revision=0` 和 `None → CANDIDATE` 开始。
- Verification `PASS`、`FAIL`、`REVIEW_REQUIRED` 分别推进到 `VERIFIED`、
  `REJECTED` 或追加 `CANDIDATE → CANDIDATE`。
- Human Approval 仅允许 Engineering Decision 与 Known Issue。
- Verification History 使用 append-only identity，不允许 replacement 或 approval。
- 延迟替代在单个 aggregate revision 中原子更新旧、新两个 Record。
- History cursor 使用 `revision:<aggregate_revision>:offset:<n>`，拒绝 stale cursor。
- terminal audit 失败后的 operation replay 命中 receipt，不重复 mutation。

## Security Boundaries

本层不进行 Agent invocation，不调用 LLM 或 RAG，不执行 Tool execution，不访问
filesystem、network、database 或 hardware operation，不读取系统时钟，不生成 UUID，
并提供 no hard delete。Memory 不调用 Verification Agent，只消费调用方提供并重新验证的
冻结 Verification request/result。Workspace Runtime 继续是工程文件的唯一写边界。

## Quality Gate Scope

发布验证在从候选 index 导出的精确 staged tree 上执行。Python 固定为 3.11，Black 固定为
Black 26.5.1；Ruff、focused/security/release/regression、全量 pytest、compileall、
pip check 和 diff check 全部属于门禁。Black 只检查本版本相对基线的 staged-change
Python manifest；全仓已有 181 个历史 Black differences 继续作为独立 formatting-only
债务，不混入 v0.39 功能提交。

## Non-goals

- real persistence、database adapter、cache 或后台任务
- Agent、LLM 或 RAG 集成
- Tool execution、Shell、Git、网络或硬件控制
- filesystem 或 Workspace mutation
- 自动修复、自动批准或 hard delete
