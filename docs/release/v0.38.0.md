# Embedded Copilot v0.38.0

## Release Scope

v0.38.0 新增 framework-independent、deterministic 的 Verification Agent Layer。它消费
调用方提供的冻结 Engineering Result，通过注入的 Firmware、Hardware 与 Tool Result
Checker 返回 `PASS`、`FAIL` 或 `REVIEW_REQUIRED`，不执行任何工程操作。

## Verification Semantics

每个 Finding 固定为 `candidate_semantics="unverified"`。`FAIL` 表示当前提案未通过验证
规则，不表示已经确认真实设备存在故障。GPIO、接口或供电冲突只说明同时提供的候选关系
不能通过当前规则；工程师仍需确认这些候选是否确实同时启用。

实现不产生 confirmed fault、hardware failure 或 root-cause claim，也不返回自动修复、执行
动作或 patch。

## Atomic Checker Batch

同一请求的多个 Checker 构成原子批次。任一 Checker 异常时立即停止，后续 Checker 不再
执行，已有部分结果不交付。Runtime 记录 `VERIFICATION_FAILED` 并抛出清洗后的
`VerificationCheckerUnavailable`，不会忽略失败 Checker 后返回 `PASS`。

## Built-in Checkers

- `FirmwareVerificationChecker`：验证 build status、error/warning count 与显式资源比例，不重新编译。
- `HardwareConstraintChecker`：验证显式 GPIO、接口与供电候选关系，不修改硬件设计。
- `ToolResultChecker`：验证 Tool status、output binding、Mock trust 与 metric 范围，不调用 Tool。

Confidence 是确定性规则的证据完整度，不是模型概率，也不由 LLM 生成。

## Audit and Security Boundary

Audit 仅包含 event type、request ID、subject type 和调用方提供的 UTC timestamp，不包含源码、
文件内容、完整硬件数据、secret 或异常原文。Runtime 不读取系统时间。

Verification Agent 不依赖 Agent、Supervisor、Model/LLM、RAG、API、Streamlit、network、
database、environment variables、Git、Shell、subprocess 或 filesystem mutation。Workspace
Runtime 仍是唯一文件写边界。

## Explicit Non-goals

v0.38.0 不提供：

- Tool execution
- Shell
- file mutation
- hardware control
- auto fix
- Agent invocation
- compilation、Flash、program、reset 或真实硬件验证
- API、UI 或 Supervisor integration

## Validation

Release gate 包含 focused Verification tests、安全边界测试、既有 Runtime regression、全量
offline pytest、Ruff、增量 Black check、compileall、pip check 与 Git whitespace checks。任何
失败都会阻止 commit 和 annotated tag。

## Quality Gate Scope

v0.38 使用 staged-change Black gate，并固定使用当前 Black 26.5.1。精确 staged v0.38
Python manifest 中的全部文件必须通过 Black；检查对象从 `git write-tree` 导出的 staged tree
获取，不以包含未暂存历史修改的工作树代替。

全仓另有 181 个在本次发布前已经存在的格式差异，不属于 v0.38 功能提交，也不在本次发布中
批量重排。该历史格式债务必须在独立的 formatting-only 提交中处理。
