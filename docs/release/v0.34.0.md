# Embedded Copilot v0.34.0

## Added

- A framework-independent, transport-neutral VS Code MCP adapter contract.
- Six deterministic tool mappings for workspace context, code/build analysis, diff review, proposal validation, and approved apply.
- Construction-time capability gating with approved apply disabled by default.

## Architecture Boundary

The VS Code MCP Integration Layer converts request arguments into existing frozen Runtime DTOs and invokes only `CodingIntelligencePort` or `WorkspacePort`. Source text, compiler logs, diffs, identifiers, and approval timestamps are caller-provided and request-scoped.

`create_change_proposal` always calls `WorkspacePort.validate_change()`. Applying a proposal requires explicit capability opt-in and a matching externally approved `ApprovalContext`; Workspace Runtime remains the only write boundary.

The adapter returns canonical JSON or fixed safe error codes. It does not expose exception text, traceback, absolute paths, concrete Runtime implementations, validators, writers, or tool handlers.

## Verification

- Focused tests cover facade isolation, frozen DTOs, fixed tool registration, argument conversion, capability denial, proposal validation, approval rejection, approved apply, and error privacy.
- Static tests block MCP SDKs, server transports, filesystem operations, Agent, Model/LLM, RAG, Streamlit, Shell, Git, network, background execution, and mutable module state.
- Coding Runtime remains read-only and Workspace Runtime remains the only mutation owner.

## Limitations

- v0.34 does not install an MCP SDK and does not start an MCP server.
- It does not implement stdio, HTTP, WebSocket, network, VS Code launch configuration, extension packaging, or a real VS Code connection.
- It does not execute builds, terminals, Git, flash operations, IDE commands, or hardware control.
- It does not create approvals, infer authorization, generate proposal identifiers, or generate timestamps.
- Code, log, and diff inputs must be supplied explicitly by a future trusted transport and are never cached or persisted by this layer.
