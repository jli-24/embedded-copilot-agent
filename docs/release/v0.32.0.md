# Embedded Copilot v0.32.0

## Added

- `embedded_copilot.coding_runtime` provides deterministic, read-only code context, project, build-log, diff, and hardware/software candidate analysis.
- The public boundary is `CodingRuntime.coding_port()` and the `CodingIntelligencePort` protocol.
- Code context snapshots are frozen, versioned, fingerprinted, and retain only normalized paths, content hashes, structural symbols, dependencies, and explicit hardware-access candidates.

## Architecture Boundary

The Coding Intelligence Layer consumes caller-provided bounded DTOs. It does not read a workspace, invoke Git, execute a compiler, call a model, modify files, control an IDE, or introduce an Agent or workflow.

C and C++ parsing uses Tree-sitter wheels; Python parsing uses the standard library AST. Hardware/software output is always an unverified candidate bound to an existing datasheet reference and requires engineer validation.

## Validation

- Focused Coding Runtime and static boundary tests cover snapshots, parsers, embedded project markers, build diagnostics, diff review, fusion candidates, and mutation-capability absence.
- The release verification suite runs offline on Python 3.11.9 with dependencies loaded from `.venv\\Lib\\site-packages`.

## Limitations

- This layer does not write code, produce patches, execute builds, or operate hardware.
- It does not claim a pin mapping or hardware/software conflict as verified.
- Workspace Runtime, VS Code integration, Probe Runtime, oscilloscope support, and hardware control are not part of v0.32.0.
