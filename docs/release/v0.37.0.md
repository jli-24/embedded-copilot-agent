# Embedded Copilot v0.37.0

## Release Scope

v0.37.0 新增 framework-independent、security-first 的 Tool Execution Layer。
它提供严格 Tool contract、不可变 registry、caller-owned permission decision、
结果规范化和同步双阶段 audit。

## Controlled Capability Adapters

本版包含三个 capability adapter：

- `compile_firmware`：仅使用构造期注入的 Mock build scenario。
- `read_serial_log`：只投影一次 Debug Runtime UART snapshot。
- `run_firmware_test`：仅使用构造期注入的 Mock firmware test scenario。

Mock build 与 test 输出始终携带不可移除的 `execution_mode="MOCK"`，不存在默认
成功或对真实 compiler、test runner、设备和 transport 的隐式调用。

## Permission and Audit Boundary

每次可信调用必须先记录 `TOOL_REQUESTED`，再经过绑定 request fingerprint、
tool name、caller 和 arguments 的 permission decision。调用结束必须且只能记录
一个 `TOOL_SUCCEEDED`、`TOOL_FAILED` 或 `TOOL_REJECTED`。

任一 audit 写入失败都会阻断结果交付。Audit 不包含命令、源代码、完整串口日志、
固件内容、secret、路径或异常文本。

## Security Boundary

Tool Runtime 不依赖 Agent、Supervisor、Model/LLM、RAG、API、Streamlit、Shell、
subprocess、Git、network、database、environment variables 或 filesystem mutation。
它不调用 legacy Agent Tool implementation，也不获得 Workspace Runtime 写能力。

Workspace Runtime 仍是唯一文件写入口。

## Explicit Non-goals

v0.37.0 不提供：

- autonomous execution
- Shell 或 arbitrary command execution
- Flash、erase、program、reset 或 hardware control
- real build
- real firmware test
- 真实 UART transport
- Agent/Supervisor、API 或 UI integration
- production hardware validation

这些限制意味着本版是受控 Tool abstraction foundation，而不是自动化执行或真实
硬件工具链。
