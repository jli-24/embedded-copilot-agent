# Embedded Copilot v0.47.0

## Release Overview

v0.47.0 adds a framework-independent, observation-only Hardware Intelligence
Layer. It produces immutable projections from caller-owned simulation, telemetry,
validation, and verified execution boundaries. It does not communicate with or
control physical hardware.

## Hardware Intelligence Architecture

```text
SUCCESS ExecutionSnapshot
  -> safe Hardware Context Projection
  -> Digital Twin Boundary
  -> structured Hardware Observation
  -> HIL Projection Boundary
  -> Human Validation Approval
  -> Validation Projection
  -> immutable Hardware Intelligence Snapshot
```

The facade exposes only `HardwareIntelligencePort`. Provider lifecycle and all
external connections remain owned by trusted composition callers.

## Digital Twin Layer

The Digital Twin Boundary accepts one typed request and returns a deterministic,
fingerprinted projection containing a model reference, safe state summary, and
finite structured metrics. The production package does not include a simulator,
device connection, or transport implementation.

## HIL Projection Layer

The HIL Projection Boundary binds scenario, digital-twin, and observation
fingerprints. It is a reference-only projection and does not start test equipment,
send commands, or execute a physical HIL scenario.

## Telemetry Model

Hardware Observation values are typed, finite, timestamped metrics supplied by a
caller-owned port. The Runtime does not collect raw logs, stdout, stderr, binary
payloads, paths, or connection details, and it does not poll or persist samples.

## Validation Boundary

Human approval is bound to the observation-ready snapshot. The injected validation
port can report schema, simulation, threshold, and contract results. `VALIDATED`
means only that these software projection checks passed; it is not physical
hardware validation or electrical certification.

## Execution Integration

Execution Integration accepts only a typed, successful, verified public Execution
Snapshot. It projects safe execution and artifact reference identifiers into a
Hardware Analysis request without reading artifact bodies or invoking an executor.

## Security Boundary

- No Agent, Supervisor, Knowledge, Memory, Tool, or protected Runtime internals.
- No filesystem, database, network, Shell, Git, compiler, or dynamic import.
- No device handles, credentials, raw output, background work, cache, or persistence.
- No physical hardware mutation or automatic operation selection.
- Provider and progress failures are converted into sanitized boundary outcomes.

## Non-goals

v0.47 does not provide physical hardware control, USB, Serial, Flash, Debug, real
HIL execution, automated test equipment, PCB validation, physical hardware
validation, or production hardware verification.
