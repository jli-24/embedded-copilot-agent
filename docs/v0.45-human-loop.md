# Embedded Copilot v0.45.0 Human Loop Layer

Status: Released

## Purpose

The Human Loop Layer establishes a framework-independent review boundary for
engineering proposals. It turns a safe, metadata-only proposal projection into
an explicit human decision and, when changes are requested, a structured
feedback projection and a new reviewable revision proposal.

```text
Engineering Generation Proposal
    -> metadata-only ProposalProjection
    -> Human Review
    -> APPROVED / CHANGES_REQUESTED / REJECTED
    -> structured FeedbackProjection
    -> RevisionContext
    -> new RevisionProposal
    -> human review again
```

## Public Boundary

`create_human_loop_runtime(...)` composes caller-owned proposal, review,
feedback, and progress ports. `HumanLoopRuntime` exposes only
`human_loop_port()`.

All public DTOs are frozen, strict, reject extra fields, use tuple collections,
and validate deterministic fingerprints. IDs and UTC timestamps are supplied
by the caller. The Runtime does not read a clock, generate identifiers, cache
review state, or persist proposals.

## Proposal and Review Safety

The v0.44 engineering proposal enters the review layer through an explicit
safe projection. The projection includes only proposal identity, artifact type,
artifact version, summary, safe reference IDs, and a fingerprint. It excludes
the artifact body, source code, CAD or PCB data, firmware, prompts, hidden
reasoning, and tool output.

Human decisions are limited to `APPROVED`, `CHANGES_REQUESTED`, and `REJECTED`.
The reviewer, decision, comment, proposal fingerprint, and caller-supplied UTC
time are bound into the decision projection. The Runtime never invents or
upgrades a human decision.

## Feedback and Revision Boundary

Feedback is a structured projection with a change type, target reference,
constraint, priority, and safe reference. Free-form review text is not executed
or interpreted by the Runtime.

A revision can be prepared only after `CHANGES_REQUESTED`. Its context binds the
original proposal, reviewed feedback, and verified Knowledge and Engineering
Memory references. The Human Loop Layer does not mutate the original artifact,
Knowledge, or Memory. A generated revision remains a proposal and must pass
human review again.

## Progress and Failure Behavior

Progress events contain only sequence, proposal ID, lifecycle state, event, and
caller-provided timestamp. Progress delivery failure is fail-closed: no partial
result is returned and no retry or background work is started.

## Security Boundary

The Human Loop Layer is independent of FastAPI, Streamlit, Agent, Supervisor,
Workflow internals, Tool Runtime, Workspace writing, device control, networking,
filesystem access, databases, shell execution, and persistence. It communicates
only through public typed Ports.

## Non-goals

v0.45 does not provide automatic approval, automatic artifact mutation, Agent
execution, Tool execution, Build, Flash, Debug, Engineering Memory writes,
Knowledge mutation, API endpoints, UI, or autonomous revision loops.
